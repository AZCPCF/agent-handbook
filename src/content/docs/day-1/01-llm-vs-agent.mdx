## خلاصه

- **LLM Call** — یک درخواست، یک پاسخ. مدل «دست» ندارد: بدون اینکه محتوا را برایش بچسبانی نمی‌تواند ریپو را بخواند یا تست اجرا کند.
- **AI Agent** — یک LLM که در یک حلقه، **خودش گام بعدی را تعیین می‌کند و ابزارها را انتخاب می‌کند** و از بازخورد محیط (نتیجه تست، محتوای فایل، خطا) برای ادامه استفاده می‌کند.
- **Agentic System** — اصطلاح چتری. هم **Workflow** (مسیرهای از پیش‌تعریف‌شده در کد) را شامل می‌شود و هم **Agent** (مسیر تعیین‌شده توسط مدل) را.

## آزمون یک‌سؤالی

> **گام بعدی را چه کسی تعیین می‌کند: کد تو یا مدل؟**

| | LLM Call | Workflow | Agent |
|---|---|---|---|
| تعیین‌کننده گام بعد | تو (یک گام) | کد تو | مدل |
| استفاده از ابزار | ندارد | دارد، در جاهای ثابت | دارد، به‌صورت پویا |
| تعداد گام‌ها | ۱ | از قبل مشخص | از قبل نامشخص |
| پیش‌بینی‌پذیری | بالاترین | بالا | کمتر |
| هزینه / تأخیر | کمترین | متوسط | بیشترین |

## یک تسک، سه شکل

تسک: *«مجموع فاکتورها در CRM اشتباه است.»*

1. **LLM Call:** تابع را می‌چسبانی؛ مدل باگ را توضیح می‌دهد.
2. **Workflow:** هر تیکت با برچسب `bug` ← کد دسته‌بندی می‌کند ← LLM خلاصه می‌کند ← کد کامنت می‌گذارد.
3. **Agent:** ریپو را جست‌وجو می‌کند، باگ را با یک تست شکست‌خورده بازتولید می‌کند، کد را ویرایش می‌کند، تست‌ها را دوباره اجرا می‌کند و وقتی سبز شد متوقف می‌شود.

## چرا این تفاوت مهم است؟

Agent انعطاف را با **هزینه، تأخیر و ریسک** می‌خرد. بخش بزرگی از مهندسی با Agent این است که تصمیم بگیری انعطاف *کجا* ارزش این قیمت را دارد.

:::tip[قاعده سرانگشتی]
ساده‌ترین شکلی را انتخاب کن که مسئله را حل می‌کند. فقط وقتی سراغ Agent برو که تعداد گام‌ها از قبل قابل پیش‌بینی نیست.
:::

## اشتباهات رایج

- هر قابلیت LLM را «Agent» نامیدن.
- دادن یک خط لوله ثابت به Agent به عنوان تسک.
- فرض اینکه پنجره چت یعنی Agent. چت یک رابط است؛ Agent یک معماری است.
