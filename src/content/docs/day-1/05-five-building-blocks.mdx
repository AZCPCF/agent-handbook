## پنج بلوک

| بلوک | به چه سؤالی جواب می‌دهد | مثال CRM |
|---|---|---|
| **Model** | چه کسی استدلال می‌کند؟ | Claude با اندازه و سطح تلاش انتخاب‌شده |
| **Tools** | چه کاری می‌تواند بکند؟ | خواندن فایل، اجرای تست، کوئری روی DB استیجینگ |
| **Context** | الان چه چیزی را می‌بیند؟ | تسک، دستورالعمل‌ها، فایل‌های مرتبط، نتایج اخیر |
| **State** | چه چیزی فراتر از این Context باقی می‌ماند؟ | لیست تسک، یادداشت پیشرفت، کامیت‌های Git |
| **Environment** | اقدام‌ها کجا اثر می‌گذارند؟ | ریپو، ترمینال، کانتینرها، APIهای خارجی |

## تعامل آن‌ها

```text
          +---------- Context (limited window) ----------+
Model <-> |  instructions + task + tool results + history |
  |       +-----------------------------------------------+
  v
Tools --> Environment (files, shell, DB, APIs)
  |
  +--> State (written outside the context, reloaded later)
```

## تمایزهای کلیدی

- **Context موقتی است؛ State ماندگار.** هر چیز مهم باید در State (فایل، Git) نوشته شود وگرنه با پر شدن پنجره از بین می‌رود.
- **Environment جایی است که ریسک آنجاست.** مجوزها اینجا تعریف می‌شوند.
- **Tools مرز عاملیت را تعیین می‌کنند.** بدون ابزار، اقدامی نیست.

## عیب‌یابی با پنج بلوک

| علامت | مظنون |
|---|---|
| یک قانون پروژه را نادیده می‌گیرد | Context |
| کار تمام‌شده را در Session بعد تکرار می‌کند | State |
| فایل اشتباه را ویرایش می‌کند | Tools / Environment |
| ضعیف استدلال می‌کند | Model |
