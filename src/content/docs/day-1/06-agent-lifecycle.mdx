## مراحل

| مرحله | چه اتفاقی می‌افتد | کنترل با |
|---|---|---|
| ۱. Intake | تسک و معیارهای پذیرش تعریف می‌شود | تو |
| ۲. Initialise | دستورالعمل‌ها بارگذاری، محیط آماده، Branch ساخته می‌شود | Harness |
| ۳. Plan | Agent کاوش می‌کند و گام‌ها را پیشنهاد می‌دهد | Agent (برای کار پرریسک تو تأیید می‌کنی) |
| ۴. Execute | حلقه اقدام و مشاهده | Agent در محدوده مجوزها |
| ۵. Verify | تست، Lint، مقایسه با معیارها | Harness + تو |
| ۶. Review | انسان یا Reviewer Agent تغییرات را بررسی می‌کند | تو |
| ۷. Integrate | Merge از طریق CI | Pipeline |
| ۸. Handoff | پیشرفت و تصمیم‌ها برای Session بعد ذخیره می‌شود | Agent + Harness |

## جریان

```text
Intake -> Initialise -> Plan -> [ Execute <-> Observe ] -> Verify -> Review -> Integrate
                                         ^                              |
                                         +------ fix and retry <--------+
                                                           Handoff -> next session
```

## نکته‌های عملی

- **کیفیت Intake سقف کیفیت را تعیین می‌کند.** تسک مبهم، کار مطمئن ولی اشتباه تولید می‌کند.
- **Verification یک مرحله است، نه یک امید.** قبل از اجرا تعریفش کن.
- **Handoff برای پروژه‌های بلندمدت اجباری است.** یک Session تازه هیچ چیز نمی‌داند مگر اینکه ذخیره کرده باشی.

## خودآزمایی

چرخه عمر «افزودن یک فیلد به فرم Customer» را بنویس و مرحله‌ای که دخالت می‌کنی را مشخص کن.
