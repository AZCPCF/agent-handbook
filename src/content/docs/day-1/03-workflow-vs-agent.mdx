## تعریف‌ها

- **Workflow:** LLMها و ابزارها از طریق **مسیرهای از پیش‌تعریف‌شده در کد** هماهنگ می‌شوند.
- **Agent:** LLM **به‌صورت پویا فرایند و استفاده از ابزار را خودش هدایت می‌کند**.

هیچ‌کدام «بهتر» نیست. این‌ها روی یک طیف از کاملاً اسکریپت‌شده تا کاملاً خودمختار قرار دارند.

## پنج الگوی Workflow

| الگو | ایده | مثال نرم‌افزاری |
|---|---|---|
| **Prompt Chaining** | دنباله ثابت؛ خروجی هر گام ورودی بعدی | پیش‌نویس Spec ← بررسی با قواعد ← نوشتن کد |
| **Routing** | دسته‌بندی ورودی و ارسال به مسیر تخصصی | تیکت‌های باگ / فیچر / سؤال |
| **Parallelization** | اجرای هم‌زمان بخش‌های مستقل یا رأی‌گیری | بررسی هم‌زمان امنیت و سبک یک PR |
| **Orchestrator-Workers** | یک مدل کار را پویا تقسیم می‌کند، Workerها اجرا می‌کنند | تغییر چندفایلی که فایل‌ها از قبل معلوم نیستند |
| **Evaluator-Optimizer** | یکی تولید می‌کند، دیگری نقد می‌کند، تکرار | تولید کد، بازبینی، اصلاح |

## ماتریس تصمیم

| سؤال | اگر بله ← |
|---|---|
| گام‌ها از قبل معلوم‌اند؟ | Workflow |
| نتیجه باید قابل بازتولید و ممیزی باشد؟ | Workflow |
| تعداد گام‌ها پیش‌بینی‌ناپذیر است؟ | Agent |
| بازخورد محیط (تست، خطا) ضروری است؟ | Agent |
| اشتباه گران یا غیرقابل‌بازگشت است؟ | Workflow + تأیید انسانی |

## ترکیبی بودن قاعده است

سیستم‌های واقعی **اسکلت قطعی با سلول‌های Agentic** هستند: کد Branch می‌سازد، CI اجرا می‌کند و تأیید می‌خواهد؛ Agent *داخل* یک گام کار می‌کند (مثلاً «تست شکست‌خورده را درست کن»).

:::caution
Frameworkها Promptها و پاسخ‌ها را پشت لایه‌های انتزاعی پنهان می‌کنند. با فراخوانی مستقیم API یا یک Harness ساده شروع کن و لایه را فقط وقتی اضافه کن که بتوانی توضیح بدهی چه می‌کند.
:::
