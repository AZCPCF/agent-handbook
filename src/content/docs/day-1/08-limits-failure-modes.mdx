## فهرست شکست‌ها

| Failure Mode | چه شکلی است | راهکار |
|---|---|---|
| **توهم (Hallucination)** | توابع یا APIهای ناموجود را صدا می‌زند | Type-check، اجرای کد، ارجاع به مستندات |
| **اعلام زودهنگام «تمام شد»** | بدون تست اعلام پیروزی می‌کند | مرحله اعتبارسنجی اجباری |
| **از دست رفتن Context** | تصمیم‌های قبلی را فراموش می‌کند | فایل پیشرفت، تسک کوچک، Compaction |
| **آلودگی Context** | مطالب نامرتبط تمرکز را خراب می‌کند | بارگذاری فایل‌ها به‌صورت Just-in-Time |
| **Scope Creep** | کد نامرتبط را Refactor می‌کند | تسک محدود، بازبینی Diff |
| **حلقه بی‌پایان** | همان اقدام شکست‌خورده را تکرار می‌کند | سقف گام، تشخیص گیر کردن |
| **سوءاستفاده از ابزار** | آرگومان اشتباه، دستور مخرب | Schema، قواعد مجوز |
| **Prompt Injection** | متن مخرب در فایل یا صفحه وب Agent را منحرف می‌کند | خروجی ابزار را غیرقابل‌اعتماد فرض کن، Sandbox |
| **اعتمادبه‌نفس کاذب** | طراحی قانع‌کننده ولی غلط | بازبینی، تست، نظر دوم |
| **انفجار هزینه** | گام‌های زیاد، Contextهای بزرگ | بودجه، مانیتورینگ |

## اصل

> فرض کن Agent **حتماً** اشتباه می‌کند. طوری طراحی کن که اشتباه **ارزان، قابل‌مشاهده و برگشت‌پذیر** باشد.

## برگشت‌پذیر در برابر غیرقابل‌بازگشت

| برگشت‌پذیر (اجازه بده) | غیرقابل‌بازگشت (Gate بگذار) |
|---|---|
| ویرایش فایل در Branch | حذف داده |
| اجرای تست | Migration روی Production |
| ساخت Commit | Deploy، Force-push |

## خودآزمایی

سه Failure Mode را انتخاب کن و تصمیم بگیر کدام برای داده‌های CRM/ERP خطرناک‌تر است.
