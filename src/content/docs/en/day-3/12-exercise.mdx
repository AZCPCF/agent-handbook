## Task

Design how agents would build the **users and roles module** for the CRM. Deliverable: `multi-agent-architecture.md`.

## Reference decomposition (pattern to adapt)

| ID | Task | Owner | Depends on | Parallel? | Human gate |
|---|---|---|---|---|---|
| T0 | Spec: roles, permissions, API contract | Planner | none | n/a | You approve |
| T1 | Schema and migration | Coder A | T0 | No | **Approve migration** |
| T2 | Permission helper with unit tests | Coder B | T0 | Yes, with T3 | No |
| T3 | API endpoints with tests | Coder C | T0, T1 | Yes, with T2 | No |
| T4 | UI screens | Coder D | T3 contract | After T3 | No |
| T5 | E2E tests | Tester | T4 | No | No |
| T6 | Review of each PR | Reviewer | each task | Per PR | You merge |

## Architecture notes to include

- **Isolation:** each coder in its own worktree, branch, port and test DB.
- **Communication:** spec and contract files in `specs/`, progress in `tasks/`.
- **Permissions:** planner and reviewer read-only; coders cannot touch production or existing migrations.
- **Limits:** at most three coder-reviewer rounds, then escalate.
- **Conflict plan:** one owner per file group; contract tests between API and UI.
