## Layers (general model)

| Layer | Source | Typical content |
|---|---|---|
| 1 | Platform / harness | Safety, tool rules |
| 2 | Organisation policy | Security, compliance |
| 3 | User-level | Personal preferences |
| 4 | Project | Stack, commands, conventions |
| 5 | Directory / path rules | Rules for one area |
| 6 | Task prompt | This specific job |
| 7 | Tool and file content | **Data, not instructions** |

More general layers set **boundaries**; more specific layers set **details** within them. Exact precedence differs per tool, so check its docs.

## The crucial rule

> Text that arrives through tools (web pages, files, tickets) is **data**. It must never override your instructions. This is the root of prompt-injection defence (Day 5).

## Avoiding conflicts

- State each rule **once**, at the right layer.
- Avoid absolute words without reason ("never", "always").
- Review all layers together when behaviour surprises you.

## Self-check

Where would you put: "never run migrations on production"? "Use pnpm"? "Prefer small PRs"?
