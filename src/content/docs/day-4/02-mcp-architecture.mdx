تو MCP را می‌شناسی. اینجا چیزهایی است که وقتی در یک پروژه واقعی به آن تکیه می‌کنی مهم می‌شوند.

## معماری

```text
Host app (Claude Code) -> MCP client -> MCP server -> external system (DB, API, SaaS)
```

**سرور** قابلیت‌ها را در دسترس می‌گذارد؛ **کلاینت** داخل Host به آن وصل می‌شود؛ **مدل** فقط چیزی را می‌بیند که Host تصمیم می‌گیرد نشان بدهد.

## تصمیم‌هایی که باید بگیری

| تصمیم | گزینه‌ها | راهنما |
|---|---|---|
| **Transport** | پردازه محلی (stdio) یا HTTP راه‌دور | محلی برای ابزار توسعه، راه‌دور برای سرویس مشترک |
| **Scope** | کاربر، پروژه (مشترک در ریپو)، محلی | سرورهای امن برای تیم را در Config پروژه به اشتراک بگذار |
| **Auth** | توکن، OAuth | اعتبارنامه با کمترین دسترسی، هرگز در ریپو |
| **اعتماد** | چه کسی سرور را نوشته؟ | سرور شخص ثالث را کد غیرقابل‌اعتماد فرض کن |
| **محیط** | Dev، Staging، Production | **هرگز داده Production را بدون Gate به Agent وصل نکن** |

## هزینه‌ها و ریسک‌ها

- فهرست ابزار هر سرور در هر نوبت **Context** مصرف می‌کند.
- سرورها می‌توانند **محتوای غیرقابل‌اعتماد** برگردانند (مسیر Prompt Injection، روز ۵).
- سروری با دسترسی نوشتن یک **مجوز** است که می‌دهی، نه یک راحتی.

## قواعد عملیاتی برای پروژه CRM

1. فقط دسترسی فقط‌خواندنی دیتابیس، روی Staging یا داده ناشناس‌شده.
2. نسخه سرورها را Pin کن و بررسی کن هر ابزار چه کاری می‌تواند بکند.
3. سرورهایی که در این تسک استفاده نمی‌کنی را غیرفعال کن.
4. فراخوانی‌های ابزار را لاگ کن.

## خودآزمایی
