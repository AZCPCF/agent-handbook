## سه Primitive

| Primitive | کنترل با | چیست | مثال |
|---|---|---|---|
| **Tools** | **مدل** | اقدام‌هایی که مدل می‌تواند صدا بزند | `create_ticket`، `run_query` |
| **Resources** | **اپلیکیشن** | داده قابل‌خواندن با URI | فایل Schema، یک صفحه مستندات |
| **Prompts** | **کاربر** | قالب‌های قابل‌استفاده مجدد که کاربر فعال می‌کند | قالب «بازبینی این PR» |

## انتخاب

| اگر نیاز داری... | استفاده کن |
|---|---|
| Agent اقدام یا محاسبه کند | Tool |
| Agent داده مرجع پایدار بخواند | Resource |
| گردش‌کار تکرارشونده که کاربر فعال می‌کند | Prompt (یا Skill) |

## نکته‌های طراحی

- برای داده مرجع بزرگ فقط‌خواندنی **Resource** را ترجیح بده تا Agent در لحظه نیاز بارگذاری کند (Just-in-Time، روز ۲).
- **Tool** را برای عملیات نگه دار؛ ابزار فقط‌خواندنی اشکالی ندارد ولی از نظر مجوز مثل Tool با آن رفتار کن.
- وقتی انسان باید تصمیم بگیرد گردش‌کار کی اجرا شود از **Prompt** استفاده کن.

:::note
پشتیبانی کلاینت‌ها از Resources و Prompts متفاوت است. قبل از طراحی بر پایه‌شان بررسی کن کلاینت تو واقعاً چه چیزی را نشان می‌دهد.
:::
