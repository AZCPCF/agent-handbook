قالب را می‌دانی (روز ۲: Progressive Disclosure). امروز درباره **طراحی Workflowهایی است که ارزش بسته‌بندی دارند**.

## چه چیزی لایق Skill است

- بیش از **دو بار** برای Agent توضیحش داده‌ای
- **گام‌های مرتب** و تعریف تمام‌شدن دارد
- اشتباه در آن گران است (رفع باگ، بازبینی Migration، Release)

## آناتومی یک Skill گردش‌کار خوب

| بخش | محتوا |
|---|---|
| **توضیح ماشه** | کی استفاده شود، با کلمات خودت |
| **گام‌ها** | کوتاه، مرتب، قابل‌اعتبارسنجی |
| **بخش‌های قطعی به‌صورت اسکریپت** | تست، Lint، بررسی داده کد هستند نه متن |
| **نرده‌ها** | چه چیزی نباید بکند، کی از تو بپرسد |
| **قالب خروجی** | گزارش نهایی چه چیزی دارد |

## Skill، Hook یا Command؟

| نیاز | استفاده |
|---|---|
| رویه‌ای که مدل با قضاوت دنبال می‌کند | Skill |
| باید هر بار اتفاق بیفتد، بدون قضاوت | Hook |
| خودت صریحاً فعالش می‌کنی | Command یا قالب Prompt |

## Skillهایت را تست کن

همان سه تسک را با و بدون Skill اجرا کن. اگر نتیجه بهتر نشد، ساده‌اش کن یا حذفش کن. Skill کد است: **بازبینی، نسخه‌دار و هرس کن**.
