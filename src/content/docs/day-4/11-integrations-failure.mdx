## اصول Integration

| اصل | چرا |
|---|---|
| **بپیچ، عریان نکن** | به Agent یک ابزار امن و تسک‌محور بده، نه API خام |
| **اعتبارنامه با کمترین دسترسی** | در صورت امکان کلید فقط‌خواندنی |
| **اول Staging** | داده واقعی و Production پشت Gate انسانی می‌مانند |
| **Secret بیرون از Context** | Environment Variable یا Secret Manager |
| **آگاهی از Rate Limit** | Backoff با ابزار است، نه مدل |

## مدیریت شکست در سطح Agent

روز اول Retry و Idempotency داخل یک ابزار را دیدیم. حالا سؤال این است که **Agent و Harness وقتی ابزار مدام شکست می‌خورد چه می‌کنند**.

| شکست | پاسخ درست |
|---|---|
| گذرا (Timeout، 503) | ابزار با Backoff Retry می‌کند؛ Agent یک نتیجه تمیز می‌بیند |
| آرگومان بد | خطای عملی برگردان؛ Agent اصلاح می‌کند |
| دسترسی رد شد | توقف و پرسیدن از تو؛ دنبال راه دور زدن نگرد |
| ابزار از کار افتاده | گزارش بده؛ داده نساز |
| شکست مکرر | Circuit Breaker: بعد از N شکست متوقف شو، خلاصه کن، Escalate کن |

## قواعدی برای دستورالعمل‌ها و کد

1. وقتی ابزار شکست می‌خورد **هرگز نتیجه نساز**؛ بگو شکست خورد.
2. مسدود شدن مجوز را با ابزار دیگر **دور نزن**.
3. Retry را برای هر ابزار و هر تسک **محدود کن**.
4. شکست‌ها را در گزارش نهایی **نشان بده**.
