## رویدادهای معمول

| رویداد | چه زمانی | کاربرد معمول | می‌تواند مسدود کند؟ |
|---|---|---|---|
| **SessionStart** | Session شروع یا ادامه می‌یابد | تزریق Branch، تیکت، محیط | خیر |
| **UserPromptSubmit** | تو Prompt می‌فرستی | افزودن Context، غربال Prompt | بله |
| **PreToolUse** | قبل از اجرای ابزار | حفاظت فایل‌ها، رد دستورهای خطرناک | بله |
| **PostToolUse** | بعد از موفقیت ابزار | Format، Typecheck، Lint، لاگ | بازخورد به Agent |
| **Notification** | Agent نیاز به توجه دارد | اعلان دسکتاپ یا چت | خیر |
| **Stop** | Agent یک نوبت را تمام می‌کند | بررسی نهایی، تأیید اینکه تست‌ها گذشته‌اند | می‌تواند ادامه را اجبار کند |
| **SubagentStop** | یک Subagent تمام می‌کند | اعتبارسنجی نتیجه‌اش | می‌تواند ادامه را اجبار کند |
| **PreCompact** | قبل از Compaction | ذخیره یادداشت‌های حیاتی | خیر |

## Matcher

بیشتر رویدادهای ابزار اجازه می‌دهند روی نام ابزار **Match** کنی (مثلاً ابزارهای ویرایش و نوشتن)، تا Hook فقط وقتی مرتبط است اجرا شود.

## قواعد طراحی

1. **سریع:** Hookها هم‌زمان اجرا می‌شوند؛ Hook کند هر گام را کند می‌کند.
2. **Matcher باریک:** بعد از هر ویرایش کل مجموعه تست را اجرا نکن؛ بررسی ارزان را اجرا کن.
3. **در موفقیت ساکت:** فقط وقتی مشکلی هست چیزی چاپ کن.
4. **Idempotent و امن:** یک Hook ممکن است بارها اجرا شود.
5. **شفاف شکست بخور:** پیامی که Agent بتواند رویش اقدام کند.

## خودآزمایی

برای تضمین اینکه تست‌ها قبل از گفتن «تمام شد» اجرا شده‌اند از کدام رویداد استفاده می‌کنی؟
