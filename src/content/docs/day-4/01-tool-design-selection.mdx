روز اول قرارداد یک ابزار را دیدیم. امروز سؤال درباره **کل سبد ابزار** است: چه ابزارهایی وجود دارند و Agent چطور درست انتخاب می‌کند؟

## ابزار بیشتر بهتر نیست

تعریف هر ابزار Context مصرف می‌کند و ابزارهای مشابه مدل را گیج می‌کنند. با زیاد شدن گزینه‌های هم‌پوشان، خطای انتخاب بالا می‌رود.

| اصل | در عمل |
|---|---|
| **ابزارهای کمتر ولی توانمندتر** | یک `search_customers` با فیلتر، بهتر از پنج ابزار تقریباً یکسان |
| **هدف روشن و متمایز** | اگر نمی‌توانی تفاوت دو ابزار را بگویی، ادغامشان کن |
| **Namespacing** | پیشوند دامنه یا سرویس: `crm_search_customers`، `crm_update_customer` |
| **شکل‌گرفته بر اساس تسک، نه API** | یک گردش‌کار («schedule_followup») را بپیچ، نه هر Endpoint سطح‌پایین را |
| **خروجی کم‌توکن** | شناسه و خلاصه برگردان؛ پرچم جزئیات اختیاری بگذار |
| **نام معنادار در نتیجه** | `customer_name` برگردان، نه فقط ID مبهم |

## انتخاب بین ابزار، اسکریپت و Skill

| نیاز | بهترین انتخاب |
|---|---|
| مدل باید آن را پویا و با آرگومان صدا بزند | ابزار (اغلب از طریق MCP) |
| رویه ثابت و قطعی | اسکریپتی که Agent اجرا می‌کند (یا Hook) |
| دانش و گام‌ها به شکل متن | Skill |
| قاعده‌ای که همیشه درست است | Project Instructions |

## ابزارهایت را ارزیابی کن

۱۰ تا ۲۰ تسک واقع‌گرایانه بنویس، Agent را اجرا کن و **Transcriptها** را بخوان: ابزار اشتباه انتخاب شد؟ آرگومان غلط؟ فراخوانی هدررفته؟ نام‌گذاری، ادغام یا بازنویسی توضیح، و دوباره اجرا.

:::tip
توضیح ابزار یک Prompt است. مثل Prompt ویرایشش کن و تستش کن.
:::
