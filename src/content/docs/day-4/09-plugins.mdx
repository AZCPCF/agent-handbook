## یک Plugin چه چیزی را بسته‌بندی می‌کند

| مؤلفه | مثال |
|---|---|
| Skills | `bug-triage-fix`، `release-checklist` |
| Custom Agents | `code-reviewer`، `repo-explorer` |
| Hooks | Typecheck بعد از ویرایش، حفاظت از Migrationها |
| MCP Servers | دیتابیس Staging، Issue Tracker |
| Commands | میان‌برهایی برای Promptهای رایج |

## چرا بسته‌بندی؟

- **یک نصب** به هر توسعه‌دهنده همان Harness را می‌دهد.
- **نسخه‌گذاری** و Changelog برای Setup Agent تو.
- **اشتراک** بین پروژه‌ها (یا انتشار).

## اصول معماری Extension

1. **مسئولیت واحد** برای هر Extension.
2. **وابستگی‌های صریح** بین مؤلفه‌ها.
3. **Least Privilege:** هر مؤلفه اعلام می‌کند چه نیاز دارد.
4. **سازگاری:** نسخه‌ها را Pin کن؛ بعد از به‌روزرسانی ابزار تست کن.
5. **حاکمیت:** Pluginهای شخص ثالث را مثل Dependency بازبینی کن، چون می‌توانند کد اجرا کنند و رفتار Agent را شکل بدهند.

:::caution
یک Plugin می‌تواند Hook و سرور بیاورد که با مجوزهای تو اجرا می‌شوند. فقط چیزی را نصب کن که خوانده‌ای.
:::

## برای پروژه سه‌ماهه

با فایل‌های ساده پروژه (`.claude/`) شروع کن. وقتی خواستی Setup را بین پروژه‌ها استفاده کنی **بعداً** به Plugin تبدیلش کن.
