## جابه‌جایی نگاه

**Prompt Engineering** عبارت‌بندی دستورالعمل‌ها را بهینه می‌کند. **Context Engineering** کل مجموعه توکن‌ها را در هر گام مدیریت می‌کند: دستورالعمل، ابزارها، فایل‌های بازیابی‌شده، حافظه، تاریخچه. هدف، کوچک‌ترین مجموعه توکن‌های پرسیگنال است که رفتار مطلوب را محتمل‌تر می‌کند.

| | Prompt Engineering | Context Engineering |
|---|---|---|
| واحد | یک Prompt | کل پنجره، در هر نوبت |
| سؤال | چطور بنویسمش؟ | الان چه چیزی باید در دید باشد؟ |
| مقیاس زمانی | یک فراخوانی | اجرای چندگامی و چندجلسه‌ای |
| ابزارها | عبارت‌بندی، مثال | انتخاب، بازیابی، فشرده‌سازی، حافظه، ابزارها |
| شکست به شکل | پاسخ مبهم | انحراف، فراموشی، نویز |

## چرا Agentها این را اجباری می‌کنند؟

حلقه Agent در هر نوبت داده جدید (نتیجه ابزار) تولید می‌کند. بدون مدیریت، پنجره از نویز پر می‌شود. پس Context Engineering **پیوسته** است، نه یک تنظیم یک‌باره.

## پنج اهرم

1. **انتخاب** اینکه چه چیزی وارد شود.
2. **بازیابی** در لحظه نیاز.
3. **فشرده‌سازی** چیزهای قدیمی.
4. **ماندگارسازی** چیزهای مهم خارج از پنجره.
5. **ایزوله‌سازی** کار در زیر-Contextها (Subagents، روز ۳).

## خودآزمایی

یک Prompt که اخیراً نوشتی را بردار. جز خود Prompt چه چیزی در Context بود؟
