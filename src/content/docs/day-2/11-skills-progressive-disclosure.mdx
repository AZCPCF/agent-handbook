## سه سطح

| سطح | چه چیزی بارگذاری می‌شود | کی |
|---|---|---|
| ۱. Metadata | نام و توضیح کوتاه | همیشه |
| ۲. بدنه Skill | دستورالعمل اصلی | وقتی Skill فعال شود |
| ۳. فایل‌های همراه | اسکریپت، مرجع، قالب | فقط اگر بدنه به آن‌ها ارجاع بدهد |

پس می‌توانی Skillهای زیادی داشته باشی با **هزینه ثابت تقریباً صفر**؛ فقط Skill فعال‌شده باز می‌شود.

## ساختار

```text
.claude/skills/fix-bug/
├── SKILL.md          # name, description, steps
├── reference.md      # deeper notes, loaded on demand
└── scripts/          # deterministic helpers
```

## نوشتن توضیح خوب

توضیح، **ماشه** است. بگو *چه می‌کند و کی باید استفاده شود*، با همان کلماتی که واقعاً در درخواست می‌نویسی.

## Skill در برابر فایل دستورالعمل

| | دستورالعمل پروژه | Skill |
|---|---|---|
| بارگذاری | هر Session | وقتی مرتبط است |
| مناسب برای | واقعیت‌های درست برای همه چیز | Workflowهای مشخص و تکرارشونده |
| اندازه | کوچک | می‌تواند بزرگ‌تر باشد |

## خودآزمایی

کدام تسک‌های تکراری تو به‌جای یک خط در فایل دستورالعمل، لایق یک Skill هستند؟
