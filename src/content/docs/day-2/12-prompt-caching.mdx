## ایده

ارائه‌دهندگان می‌توانند **یک پیشوند تکراری** از Prompt را Cache کنند. وقتی فراخوانی بعدی با همان پیشوند شروع شود، پردازش آن بخش ارزان‌تر و سریع‌تر است. حلقه Agent در هر نوبت همان پیشوند را دوباره می‌فرستد، پس Caching بسیار مهم است.

## پیامدهای طراحی

| انجام بده | چرا |
|---|---|
| محتوای **پایدار** را اول بگذار (System، ابزارها، دستورالعمل‌ها) | پیشوند قابل‌استفاده مجدد را بیشینه می‌کند |
| محتوای **متغیر** را آخر بگذار | تغییرهای دیرهنگام پیشوند را خراب نمی‌کنند |
| وسط Session، Context ابتدایی را ویرایش نکن | هر تغییر، آنچه بعدش می‌آید را باطل می‌کند |
| وسط تسک، فهرست ابزار و دستورالعمل را عوض نکن | همان دلیل |

```text
[ system | tools | project instructions ]  <- stable, cacheable
[ history | tool results | new message ]   <- volatile
```

## اثر عملی

- Sessionهای طولانی با پیشوند پایدار ارزان‌تر از ظاهرشان‌اند.
- ویرایش‌های مکرر فایل دستورالعمل در آغاز Session، استفاده مجدد از Cache را کم می‌کند.
- Cache منقضی می‌شود؛ قواعد دقیق و قیمت‌ها بین ارائه‌دهندگان فرق دارد، پس در مستندات فعلی بررسی کن.
