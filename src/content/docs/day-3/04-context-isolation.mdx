## ایده

هر Subagent پنجره جدا دارد. نویز کاوشش همان‌جا می‌ماند؛ فقط نتیجه تقطیر‌شده برمی‌گردد. این همان Context Engineering روز دوم است که در سطح معماری اعمال می‌شود.

```text
Main context:  [goal][plan][summary A][summary B]   <- stays small
Subagent A:    [brief][100 file reads][greps][...]   <- thrown away
Subagent B:    [brief][test runs][logs][...]         <- thrown away
```

## مزایا و هزینه‌ها

| مزیت | هزینه |
|---|---|
| Context اصلی تمیز می‌ماند | اطلاعات در مرز از دست می‌رود |
| Prompt تخصصی برای هر نقش | خواندن تکراری بین Agentها |
| مجوز جدا برای هر Agent | مصرف کل توکن بیشتر |
| کار موازی ممکن می‌شود | خلاصه‌ها می‌توانند غلط یا مبهم باشند |

## قرارداد بازگشت

نتیجه را به شکلی بخواه که برای تصمیم بعدی Lead مناسب است:

- اول یک **پاسخ کوتاه**
- **شواهد** به‌صورت مسیر فایل و شماره خط، نه دامپ کد
- **سؤال‌های باز** و ریسک‌ها
- یک **سقف طول** مشخص

:::caution
«کار می‌کند» از طرف Subagent را هرگز مدرک ندان. با تست یا یک نگاه دوم اعتبارسنجی کن.
:::
