## چرا تقسیم کنیم؟

تسک‌های بزرگ Context Window را سرریز می‌کنند و قابلیت اعتماد را پایین می‌آورند. هر گام اضافه‌ای که Agent بدون اعتبارسنجی برمی‌دارد، احتمال انحراف را چند برابر می‌کند. تقسیم تسک **مهم‌ترین مهارت** در مدیریت Agentهاست.

## زیرتسک خوب چه ویژگی‌هایی دارد

| ویژگی | معنی |
|---|---|
| **کوچک** | در یک Session و یک PR قابل‌بازبینی جا می‌شود |
| **قابل‌اعتبارسنجی** | تست یا معیار پذیرش دارد |
| **مستقل** | ورودی و خروجی روشن دارد |
| **مرتب بر اساس وابستگی** | پیش‌نیازها صریح‌اند |

## Hierarchical Planning

از درشت به ریز برنامه‌ریزی کن؛ جزئیات را فقط وقتی به آن رسیدی اضافه کن.

| سطح | مثال (کاربران و نقش‌ها در CRM) | مالک |
|---|---|---|
| Goal | کاربران می‌توانند نقش و مجوز داشته باشند | تو |
| Epic | مدل مجوز، API، UI | تو |
| Feature | «اختصاص نقش به کاربر» | تو + Agent برنامه‌ریز |
| Task | افزودن جدول `roles` و Migration | Agent (Migration را انسان تأیید می‌کند) |
| Step | نوشتن تست شکست‌خورده، پیاده‌سازی، اجرا | Agent |

## تقسیم بد در برابر خوب

| بد | خوب |
|---|---|
| «ماژول نقش‌ها را بساز» | «Schema و Migration نقش‌ها»، «تابع `can(user, action)` با تست» |
| تسک‌هایی که ده فایل را لمس می‌کنند | هر تسک یک دغدغه |
| وابستگی‌های پنهان | فهرست وابستگی برای هر تسک |
| بدون معیار تمام‌شدن | اول معیار پذیرش نوشته می‌شود |

:::tip
اگر نمی‌توانی در یک جمله بگویی چطور یک تسک را اعتبارسنجی کنی، هنوز به‌اندازه کافی تقسیم نشده است.
:::
