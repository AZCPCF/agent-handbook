## کانال‌های ارتباط

| کانال | چطور کار می‌کند | نکته |
|---|---|---|
| **Brief و Summary** | Lead Brief می‌دهد، Summary می‌گیرد | ساده‌ترین و مقاوم‌ترین |
| **Artifactهای مشترک** | Spec، فایل تسک، یادداشت پیشرفت در ریپو | ماندگار و قابل بازبینی |
| **Git** | Branch، Commit، PR | نقطه طبیعی ادغام |
| **پیام مستقیم** | Agentها به هم پیام می‌دهند | قدرتمند ولی کنترلش سخت |

ارتباط **مبتنی بر Artifact** را ترجیح بده: ردپای ممیزی می‌گذارد و از ریست Session جان به در می‌برد.

## قواعد Shared State

1. **هر تکه State یک مالک دارد** (فایل، جدول، تسک).
2. در صورت امکان **یک نویسنده**؛ بقیه فقط می‌خوانند.
3. **اول قرارداد:** پیش از کار موازی، Interface یا Schema را در Spec بنویس.
4. تصمیم‌ها را در فایل ثبت کن، نه فقط در چت.

## انواع تعارض و رفع آن

| تعارض | مثال | راه‌حل |
|---|---|---|
| **متنی** | دو Branch یک فایل را ویرایش کرده‌اند | مرز مالکیت؛ ادغام توسط انسان یا Agent ادغام‌کننده |
| **معنایی** | API مقدار `role_id` می‌دهد، UI `roleId` انتظار دارد | قرارداد مشترک و Contract Test |
| **کار تکراری** | دو Agent یک Helper را اضافه کرده‌اند | تابلوی تسک با Claim |
| **تعارض اولویت** | Agentها درباره رویکرد اختلاف دارند | Lead تصمیم می‌گیرد؛ به تو Escalate می‌شود |
