## تعریف

**Delegation** یعنی Agent اصلی یک کار مستقل را به Agent دیگری می‌سپارد. **Subagent** در **Context تازه و جداگانه** خودش اجرا می‌شود، کار را انجام می‌دهد و یک **خلاصه نتیجه** به Agent اصلی برمی‌گرداند.

```text
Lead agent --(brief)--> Subagent  [own context, own tools]
Lead agent <--(summary)-- Subagent
```

## کی Delegate کنیم

| Delegate کن | Delegate نکن |
|---|---|
| کاوش پرنویز (جست‌وجوی ریپو، خواندن فایل‌های زیاد) | ویرایش‌های کاملاً وابسته که فهم مشترک می‌خواهند |
| تسک‌های مستقل که موازی اجرا می‌شوند | تسک‌های خیلی کوچک (سربار بیش از فایده) |
| نقش‌های تخصصی (Reviewer، نویسنده تست) | تصمیم‌هایی که Context کامل تو را می‌خواهند |
| کار با مجوزهای متفاوت | هر چیزی که بعداً نمی‌توانی اعتبارسنجی کنی |

## Brief (چیزی که تحویل می‌دهی)

Subagent **هیچ چیز** نمی‌داند جز Brief. این‌ها را بگنجان:

1. **هدف:** تمام‌شدن چه شکلی است.
2. **Context:** فقط واقعیت‌های لازم، با مسیر فایل.
3. **محدودیت‌ها:** به چه چیزی نباید دست بزند.
4. **قالب خروجی:** چه چیزی و در چه اندازه برگرداند.

## سؤال‌های معماری

- چه کسی می‌تواند Agent **بسازد**؟ (معمولاً فقط Lead)
- هر کدام چه **ابزار و مجوزی** دارند؟ (Least Privilege)
- **قرارداد بازگشت** چیست؟ (خلاصه، نه کل متن)
- **شرط توقف و بودجه** چیست؟

## خودآزمایی

یک Brief برای Subagentی بنویس که همه جاهای محاسبه مجموع فاکتور را پیدا می‌کند.
