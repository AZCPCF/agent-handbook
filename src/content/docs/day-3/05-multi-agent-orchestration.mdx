## الگوهای اصلی

| الگو | شکل | مثال CRM |
|---|---|---|
| **Orchestrator-Workers** | Lead کار را تقسیم می‌کند، Workerها اجرا می‌کنند، Lead ادغام می‌کند | Lead تسک‌های Schema، API و UI را واگذار می‌کند |
| **Pipeline** | زنجیره ثابت متخصص‌ها | Planner ← Coder ← Tester ← Reviewer |
| **Fan-out / Fan-in** | چند Agent روی بخش‌های مستقل، بعد ادغام | بازبینی یک PR از نظر امنیت، سبک و کارایی |
| **Generate-and-Critique** | یکی تولید می‌کند، دیگری نقد می‌کند، تکرار | Coder و Reviewer تا برآورده شدن معیارها تکرار می‌کنند |

```text
            +-------- Lead / Orchestrator --------+
            |  plan, assign, integrate, decide    |
            +------+---------------+--------------+
                   v               v
              Worker A         Worker B       (own context, own tools)
```

## ساده شروع کن

سیستم‌های چند-Agent **توکن بیشتر، هماهنگی بیشتر و Failure Mode بیشتر** دارند. فقط وقتی Agent اضافه کن که بتوانی فایده را اسم ببری:

- تسریع موازی
- ایزوله کردن کار پرنویز
- بررسی مستقل
- مجوزهای متفاوت

## شکست‌های رایج

| شکست | پیشگیری |
|---|---|
| Workerها کار تکراری می‌کنند | مالکیت روشن برای هر تسک |
| تصمیم‌های ناسازگار | Spec مشترک پیش از کدنویسی |
| Lead کنترل را از دست می‌دهد | تعداد کم Agent، قرارداد بازگشت صریح |
| فرار هزینه | بودجه و سقف گام برای هر Agent |
